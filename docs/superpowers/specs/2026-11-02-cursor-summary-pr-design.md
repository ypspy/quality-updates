# 커서 지식체계 요약을 베지 PR로 넘기기

상태: 설계 승인됨. 구현 계획: [2026-11-02-cursor-summary-pr.md](../plans/2026-11-02-cursor-summary-pr.md)

커서 대화 끝에 지식체계 요약이 생기면, 그 요약만 `ypspy/my-obsidian-vault`의 PR로 연다. 리뷰어는 베지다. 베지가 확인하고 케일에게 넘기면, 케일이 머지하고 노트를 PARA 위치로 옮긴다. main에는 직접 push하지 않는다.

## 경계

요약 전달은 사용자 훅이다. `~/.cursor/hooks.json`의 `stop` 이벤트가 스크립트를 실행한다. 품질관리 사이트 코드와 이 저장소의 프로젝트 훅은 쓰지 않는다. 어느 작업 폴더에서 대화가 끝나도 같은 훅이 돈다.

훅 실패는 대화를 막지 않는다. `stop` 후속 루프는 만들지 않는다.

## 언제 여나

에이전트 응답이 끝난 뒤, 마지막 응답에 지식체계 요약이 있을 때만 PR을 만든다.

요약은 다음 일곱 항목이 한 덩어리로 있는 블록이다. 응답의 다른 글은 노트에 넣지 않는다.

- 유형: 결정, 결과, 현황, 이슈 중 하나
- 프로젝트
- 날짜: `YYYY-MM-DD`
- 요약
- 근거
- 다음 액션
- 미결

일곱 항목이 다 없으면 PR을 만들지 않는다. 대화 전문, 코드 블록, 도구 출력은 노트에 넣지 않는다. 같은 대화에서 훅이 다시 돌아도 PR은 하나다. 대화 ID를 로컬 장부 `~/.cursor/kale-inbox-sent.json`에 적고, 그 ID가 있으면 건너뛴다.

## 노트와 PR

브랜치 이름은 `inbox/YYYY-MM-DD-<대화 ID 앞 8자>`다. 파일은 `02-Areas/Bot-Operations/inbox/YYYY-MM-DD-<프로젝트 슬러그>-<대화 ID 앞 8자>.md` 하나다. 슬러그는 프로젝트 값에서 파일명에 쓸 수 없는 문자를 하이픈으로 바꾼 것이다. 대화 ID를 파일명에 넣어, 같은 날 같은 프로젝트의 다른 대화가 한 파일을 덮지 않는다.

노트 앞머리는 보관함 형식이다. `title`, `date`, `tags`를 둔다. 태그는 `inbox`와 유형이다. 본문은 일곱 항목만 적는다.

PR 제목은 `inbox: <프로젝트> <날짜>`다. 본문 첫 줄은 "베지가 확인하고 케일에게 넘긴다. 케일이 머지한 뒤 이 파일을 PARA 위치로 옮긴다."이다. 이어서 노트와 같은 일곱 항목을 적는다. 베이스는 `main`이다.

리뷰어는 설정 파일의 GitHub 로그인이다. 설정 파일은 `~/.cursor/kale-inbox.json`이고, 항목은 `repo`, `reviewer`, `base`다. `repo` 기본값은 `ypspy/my-obsidian-vault`, `base` 기본값은 `main`이다. `reviewer` 기본값은 없다.

## 실패

다음이면 PR을 열지 않고 `~/.cursor/kale-inbox.log`에 한 줄 남긴다. 채팅의 요약은 그대로다.

- `reviewer`가 비어 있다.
- `gh` 로그인이 없거나, 그 저장소에 PR을 열 권한이 없다.
- 푸시가 거절된다. force push는 하지 않는다.
- 원격에 같은 브랜치의 PR이 이미 열려 있다. 장부에 그 PR 주소를 적고 끝낸다.

## 확인

- 일곱 항목이 있는 응답은 노트 한 장과 PR 생성 인자로 바뀐다. 테스트는 `gh`를 호출하지 않고 인자만 검사한다.
- 항목이 빠진 응답은 장부에 남지 않고 PR 인자를 만들지 않는다.
- 같은 대화 ID로 두 번 실행하면 두 번째는 인자를 만들지 않는다.
- `reviewer`가 비어 있으면 인자를 만들지 않고 로그를 남긴다.

## 범위 밖

- 케일 리포 main에 직접 커밋하거나 push하지 않는다.
- 베지가 머지하거나 노트를 PARA로 옮기는 동작은 만들지 않는다. 그 일은 베지와 케일이 한다.
- 요약이 없는 대화를 PR로 만들지 않는다.
- 품질관리감리 본문, F004 수집, 사이트 배포는 이 설계에서 바꾸지 않는다.
